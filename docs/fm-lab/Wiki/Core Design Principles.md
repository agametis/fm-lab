Beyond its technical architecture, FM-Lab is guided by a small set of core design principles that define how users and agents interact with the information it exposes.

## Structure is knowledge

The structure of a solution is knowledge in its own right. Dependencies, references, hierarchies, naming conventions, and relationships between objects are not merely implementation details—they describe how a system works. FM-Lab makes these implicit connections explicit by transforming them into a navigable knowledge graph. The more structural information becomes visible, queryable, and reusable, the more valuable the project becomes as a foundation for analysis, documentation, and agentic reasoning.

## Every interface element is an interaction layer

Information should never be a dead end. Every interface element is designed as an entry point into deeper exploration, allowing users and agents to navigate seamlessly across the connected knowledge space. A script step leads to referenced fields and layouts, dashboards link directly to the underlying objects, analyses reveal their sources, and documentation connects back to the implementation. Rather than presenting isolated views, FM-Lab turns every result into an interactive layer that encourages discovery and accelerates understanding.
